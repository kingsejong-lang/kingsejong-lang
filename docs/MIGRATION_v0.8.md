# v0.7 → v0.8 마이그레이션 가이드

v0.7.0(2026-11-03) 에서 동작하던 코드가 v0.8.0 에서 다르게 동작하거나 더 동작하지 않는 지점을 모았다. 전체 변경 목록은 [CHANGELOG.md](../CHANGELOG.md) 의 `[Unreleased]` 절(릴리스 때 `[v0.8.0]` 절이 된다)에 있고, 이 문서는 그중 기존 코드나 사용 방법을 바꿔야 하는 항목만 다룬다.

v0.8 의 변경은 libc 의 여러 영역(문자 분류, 진법 변환, 큰 정수, 날짜)을 KingSejong 코드로 다시 쓰다가 부딪힌 문제를 고친 것이다. 각 문제와 결정은 [표준 라이브러리 수준 언어 준비도](./design/STDLIB_READINESS.md) 6장에 있다.

## 1. 실수

- **실수를 문자열로 바꾸는 규칙이 Python 과 같다.** 되읽으면 같은 값이 되는 가장 짧은 자릿수를 쓰고, 정수 값이면 `.0` 을 붙인다. 지수가 16 이상이거나 -5 이하면 지수 표기다. v0.7 에서는 유효숫자 6자리(`0.3`, `3`, `1.41421`)였고 문자열 보간만 소수 6자리(`0.500000`)였다. `출력`, `문자열()`, 보간이 이제 같은 규칙을 쓴다. 실수를 출력하는 프로그램은 결과가 달라지므로, 출력을 기대값과 비교하는 테스트는 기대값을 다시 만든다.

  ```ksj
  출력(0.1 + 0.2)              # 0.30000000000000004  (v0.7: 0.3)
  출력(실수(3))                # 3.0                  (v0.7: 3)
  출력(10000000000000000.0)    # 1e+16
  x = 2.5
  출력("값: ${x}")             # 값: 2.5              (v0.7: 값: 2.500000)
  ```

- **실수 `==`·`!=` 는 정확히 비교한다.** v0.7 에서는 차가 `1e-9` 보다 작으면 같다고 봐서 `0.1 + 0.2 == 0.3` 이 참이었다. `assert_같음`·`assert_다름` 도 정확히 비교한다. 오차를 허용하려면 차를 직접 비교하거나, 테스트에서는 `assert_근사(실제, 기대)` 를 쓴다.

  ```ksj
  출력(0.1 + 0.2 == 0.3)                      # 거짓  (v0.7: 참)
  출력(절대값((0.1 + 0.2) - 0.3) < 1e-9)      # 참
  ```

- **`정수(문자열)`·`실수(문자열)` 은 문자열 전체가 수여야 한다.** 앞뒤 공백은 허용하고, 남는 글자가 있으면 오류다. v0.7 에서는 앞부분만 읽어 `정수("12abc")` 가 `12`, `실수("3.5kg")` 가 `3.5` 였다. `정수("3.7")` → `3` 처럼 실수 모양은 그대로 받는다. 16진수 문자열(`"0x10"`)은 `stdlib/convert` 의 `정수_파싱` 으로 읽는다.

  ```ksj
  시도 {
      출력(정수("12abc"))
  } 오류 (e) {
      출력("오류")             # 오류  (v0.7: 12)
  }
  출력(정수(" 42 "))           # 42
  ```

## 2. 언어 동작

- **`그리고`·`또는`(`&&`·`||`)는 왼쪽으로 결과가 정해지면 오른쪽을 평가하지 않는다.** 결과 값은 같지만, 오른쪽 식의 부작용(함수 호출, 출력, 오류)이 더는 일어나지 않는다. 오른쪽의 함수가 늘 불리기를 기대한 코드는 그 호출을 따로 문장으로 뺀다.

  ```ksj
  횟수 = 0
  함수 센다() {
      횟수 = 횟수 + 1
      반환 참
  }
  결과 = 거짓 그리고 센다()
  출력(횟수)   # 0  (v0.7: 1)
  ```

- **조사(`가`, `을`, `은` 등)는 변수나 매개변수 이름이 될 수 없다.** v0.7 에서는 `가 = 1` 을 받아들였지만 그 변수를 식에서 읽을 수 없었다. 이제 선언하는 곳에서 구문 오류다. `x`, `가_값` 처럼 다른 이름을 쓴다.

## 3. 가져오기와 stdlib

- **가져오기가 이미 있는 함수를 다른 함수로 덮으면 실행 오류다.** v0.7 에서는 나중에 가져온 모듈의 함수가 앞서 정의하거나 가져온 같은 이름의 함수를 말없이 덮어썼다. 충돌하면 그 모듈의 이름은 하나도 들어오지 않는다. 한쪽 이름을 바꾼다. 같은 모듈을 여러 경로로 가져와 같은 함수가 오는 것은 괜찮다. 함수를 가져오기 뒤에서 정의하면 충돌이 아니라 그 정의가 이긴다.

  ```ksj
  최댓값 = 함수(a, b) {
      반환 a
  }
  가져오기 "stdlib/math"
  # 실행 오류: 가져오기 이름 충돌: 'stdlib/math' 의 '최댓값' 이(가) 이미 있는 이름과 같습니다.
  ```

- **`_` 로 시작하는 이름은 가져오지 않는다.** 모듈 안에서만 쓰는 이름이다. 이에 맞춰 KingSejong 코드로 쓴 stdlib 모듈(`bigint`, `bytes`, `convert`, `date`, `search`, `text`)의 보조 함수 47개와 `date` 의 지정자 표 3개에 `_` 를 붙였다(`변환_부호` → `_변환_부호`). 이 보조 함수를 직접 부르던 코드는 "정의되지 않은 식별자" 오류가 나므로 공개 함수로 바꾼다. 공개 함수 목록은 [STDLIB_REFERENCE.md](./STDLIB_REFERENCE.md) 에 있고, 보조 함수는 "비공개" 로 표시되어 있다.

  ```ksj
  가져오기 "stdlib/convert"
  # v0.7: 출력(변환_부호("-"))  → v0.8 에서는 정의되지 않은 식별자
  출력(정수_파싱("-ff", 16))   # -255
  ```

- **`stdlib/convert` 의 `실수_파싱` 이 가장 가까운 실수로 정확히 반올림한다.** 내장 `실수()` 와 같은 값을 낸다. v0.7 에서는 일부 입력에서 마지막 자리가 달랐다. 유효숫자가 15자리를 넘거나 지수가 ±22 를 넘는 입력은 `stdlib/bigint` 로 계산하므로 평가기에서 한 번에 약 10ms 가 걸린다.

## 4. 도구

- **파일을 실행하면 실행 한도 없이 끝날 때까지 돈다.** v0.7 에서는 평가 1000만 번(VM 명령 1억 개) 또는 5초에서 "무한 루프 의심" 오류로 멈췄다. 한도가 필요하면 `--max-time 초` 를 준다. `--sandbox`·`--untrusted`, REPL, 웹 플레이그라운드는 전과 같은 한도를 쓴다.

  ```bash
  kingsejong --max-time 10 긴_작업.ksj
  ```

- **`kingsejong fmt --check` 는 파일을 고치지 않는다.** 포맷이 필요한 파일 이름을 출력하고 종료 코드 1 로 끝난다. v0.7 에서는 플래그를 무시하고 마지막 파일을 제자리에서 고쳐 썼다. 파일을 여러 개 주면 모두 처리하고, 모르는 옵션은 오류다. CI 에서 포맷을 검사하던 스크립트는 이제 실패를 제대로 알린다.
- **린터는 `_` 로 시작하는 변수와 매개변수를 쓰지 않아도 알리지 않는다.** 쓰지 않는 매개변수를 의도한 경우 이름 앞에 `_` 를 붙인다.
