# 표준 라이브러리 수준 언어 준비도

> C 의 libc 정도 되는 표준 라이브러리를 KingSejong 코드로 직접 쓸 수 있으려면 언어에 무엇이 더 필요한지 정리한다.

**작성**: 2026-11-03 (v0.6.0 + `main` `ed0e758` 기준)
**근거**: [kingsejong-examples](https://github.com/kingsejong-lang/kingsejong-examples) 를 쓰면서, 그리고 아래 각 항목의 짧은 프로그램을 `kingsejong` 으로 직접 실행해서 확인했다.

---

## 1. 목표와 판단 기준

libc 는 문자열(`string.h`), 문자 분류(`ctype.h`), 변환·정렬·난수(`stdlib.h`), 입출력(`stdio.h`), 수학, 시간으로 이루어진다. 이 함수들 대부분은 다음 다섯 가지 언어 기능만 있으면 언어 자신으로 쓸 수 있다.

1. 문자열의 글자 하나를 읽고, 글자와 코드 값을 오간다 (`s[i]`, `ord`/`chr`)
2. 반복을 중간에 끝내거나 건너뛴다 (`break`/`continue`)
3. 정수의 비트를 다룬다 (`& | ^ ~ << >>`, 16진수 리터럴)
4. 정수 연산의 경계가 정의되어 있다 (오버플로가 어떻게 되는지)
5. 비교 함수를 받는 정렬, 컨테이너 크기 같은 기본 연산이 모든 컨테이너에 있다

아래 2장은 이미 고친 것, 3장은 빠진 기능, 4장은 사용자가 정해야 하는 언어 설계 문제다.

## 3. 빠진 기능

각 항목의 "확인" 은 실제로 돌린 코드와 결과다. "호환성" 은 기존 프로그램이 달라지는지다.

### 3.1 반복 제어 (`break` / `continue`) — 완료 (#101)

- **결과**: `중단` / `계속` 을 추가했다. 평가기와 VM 이 같은 결과를 낸다(`tests/LoopControlTest.cpp`).
- **남은 제약**: VM 은 `마지막` 블록 안의 `중단`·`계속` 을 컴파일 오류로 거부한다(평가기는 지원).
- **호환성**: `중단`·`계속` 은 이제 변수 이름으로 쓸 수 없다. 저장소의 `stdlib/`, `examples/` 에는 식별자로 쓰는 곳이 없었다.

### 3.2 문자열 글자 접근과 코드 값 — 완료

- **확인**: `"안녕"[0]` → `배열 또는 딕셔너리가 아닌 값에 인덱스 접근`. 글자↔코드 값 내장 함수가 없었다.
- **필요한 이유**: `isdigit`, `toupper`, `atoi`, 해시, UTF-8 처리.
- **결과**: 읽기 전용 `s[i]` 와 `s[a부터 b까지]` (글자 단위, 음수 인덱스·step 은 배열과 같다), `문자코드(글자)`, `코드문자(정수)` 를 추가했다. 문자열은 지금처럼 바꿀 수 없다(`s[0] = "x"` 는 오류). 평가기와 VM 이 같은 코드(`Evaluator::indexValue`, `sliceValue`)를 쓴다(`tests/StringIndexTest.cpp`).
- **남은 제약**: 문자열은 UTF-8 바이트로 저장하므로 `s[i]` 는 앞에서부터 i 글자를 센다. 인덱스로 문자열을 훑는 반복문은 여전히 O(n²) 이다. 긴 문자열은 `분리(s, "")` 로 글자 배열을 한 번 만들어 훑는다.
- **호환성**: 오류이던 식이 값을 갖게 되는 것뿐이라 기존 프로그램은 바뀌지 않는다. 내장 함수 이름 두 개(`문자코드`, `코드문자`)를 새로 쓴다.

### 3.3 비트 연산과 숫자 리터럴 — 완료

- **확인**: `5 & 3` → 렉서가 `&` 를 `ILLEGAL` 로 읽었다. `0xFF`, `0b101`, `1e10` → 구문 오류였다.
- **필요한 이유**: 해시, 플래그, Base64·UTF-8 인코딩, 체크섬. 지금 `stdlib/crypto` 의 해시는 C++ 내장 함수에 기대고 있다.
- **결과**: `&`, `|`, `^`, `~`, `<<`, `>>` 를 정수에만 허용하고, `0x`·`0b`·지수 리터럴을 추가했다(`tests/BitwiseTest.cpp`).
  - 우선순위는 Python 과 같이 비교보다 강하다(`x & 1 == 0` 은 `(x & 1) == 0`). C 처럼 비교보다 약하면 이 식이 `x & (1 == 0)` 이 되어 흔한 실수가 된다.
  - 이동 거리는 0~63 만 허용한다(C++ 에서 정의되지 않은 동작). `<<` 는 밀려난 비트를 버리고 오버플로 오류를 내지 않는다(Go·Rust 와 같다). 해시·비트 마스크 계산이 의도이기 때문이다.
  - 16진수·2진수 리터럴은 64비트 비트 패턴이다(Java 와 같다). FNV 같은 64비트 해시 상수(`0xcbf29ce484222325`)를 그대로 쓸 수 있다.
  - 포매터는 작성자가 쓴 진법·지수 표기를 지킨다.
- **호환성**: 한 글자 `&`, `|`, `^`, `~` 와 `<<`, `>>` 는 전에는 쓸 수 없던 문자라 충돌이 없다. `&&`, `||` 는 그대로다. `0x`·`e` 뒤에 자릿수가 없으면 전처럼 숫자와 식별자로 나뉜다.

### 3.4 정수 오버플로 — 완료

- **확인**: `9223372036854775807 + 1` → `-9223372036854775808`. 평가기가 `int64_t` 덧셈을 그대로 하므로 C++ 에서는 정의되지 않은 동작이었다.
- **결과**: 4.2 의 결정대로 넘치면 실행 오류, 감싸 돌기는 `감싸더하기`·`감싸빼기`·`감싸곱하기` 로 한다. 함께 정의되지 않은 동작이던 `제곱`·`정수`·`반올림`·`올림`·`내림`·`절대값` 의 범위 밖 변환과, 끝 값이 정수 끝인 범위 반복문도 고쳤다(`tests/IntegerOverflowTest.cpp`).

### 3.5 컨테이너 기본 연산 — 완료

| 확인 | 결과 | 제안 |
|---|---|---|
| `길이({"a": 1})` | `길이() 함수는 문자열 또는 배열 타입이어야 합니다` | 딕셔너리는 키 개수 — 완료 |
| `[3, 1, 2]를 정렬한다(함수(a, b) { 반환 b - a })` | `알 수 없는 배열 메서드 '정렬한다'` | 비교 함수를 받는 정렬 (`qsort` 대응) — 완료 |
| `각각` (토큰은 `Token.cpp` 에 있음) | `'GAKGAK'으(로) 시작하는 표현식을 파싱할 수 없습니다` | 요소 반복문으로 연결 — 완료. `컬렉션 각각에 대해 변수로 { }` (설계 문서 `FEATURES.md` 의 형태). 배열은 요소, 문자열은 글자, 딕셔너리는 키(정렬 순). `중단`/`계속` 과 회차별 범위는 범위 반복과 같다(`tests/ForEachTest.cpp`) |

- **결과**: `길이(딕셔너리)` 는 키 수를 돌려준다. `정렬한다(비교 함수)` 는 비교 함수가 음수를 돌려주면 앞 요소를 앞에 두는 안정 정렬이다(직접 짠 병합 정렬. 표준 라이브러리 정렬은 일관되지 않은 비교 함수에서 정의되지 않은 동작이다). 비교 함수가 수가 아닌 값을 돌려주면 오류다. 일관되지 않은 비교 함수에도 요소를 잃거나 배열 밖을 읽지 않는다(`tests/ContainerOpsTest.cpp`).

### 3.6 프로그램 바깥과의 경계 — 완료

- **명령줄 인자** — 완료: `명령줄_인자()` 가 `[스크립트 경로, 인자...]` 를 돌려준다(`main(argc, argv)` 대응). 스크립트 이름 뒤의 위치 인자는 전에 "파일은 하나만" 오류였으므로 기존 실행 방법은 바뀌지 않는다. `-` 로 시작하는 인자는 `--` 뒤에 쓴다.
- **표준 오류 출력** — 완료: `오류_출력(...)` 은 `출력` 과 같은 모양으로 표준 오류에 쓴다. 순서가 섞이지 않도록 표준 출력을 먼저 비운다. 플레이그라운드는 두 출력을 함께 보여 준다.
- **바이트 단위 입출력** — 완료: `파일_바이트_읽기(경로)` 는 0~255 정수 배열을, `파일_바이트_쓰기(경로, 바이트들)` 는 그 배열을 바이너리로 쓴다. 쓰기는 모든 요소를 먼저 검사해 잘못된 값이 있으면 파일을 건드리지 않는다. 보안 모드(`--sandbox`) 검사는 다른 파일 함수와 같다(`tests/ProcessIOTest.cpp`).
- **문자열과 바이트 변환** — 완료: `stdlib/bytes` 의 `UTF8_인코딩`/`UTF8_디코딩` (KingSejong 코드, 6장).
- **종료 코드**: `프로세스_종료(코드)` 가 있다. 결함 없음.

### 3.7 성능 (뒤로 미룸)

- 재귀 깊이는 #97 이후 약 5000 에서 실행 오류로 멈춘다. 트리를 걸으며 평가하는 구조라 호출 하나가 C++ 프레임 여러 개를 쓴다.
- 인덱스(`s[i]`, `부분문자열`)로 글자를 꺼내는 루프는 O(n²) 이다. 글자 오프셋을 기억해 두지 않고 매번 앞에서부터 세기 때문이다.
- `문자열 = 문자열 + x` 를 반복하면 매번 전체를 복사해 O(n²) 이다. 지금은 조각을 배열에 모아 `조각_잇기`(`stdlib/bytes`)로 합친다.
- 빈 반복 1억 번이 평가기·VM 모두 약 25초다(2026-11-04, macOS). VM 이 평가기보다 빠르지 않다.
- 성능 개선은 위 기능을 갖춘 뒤에 다룬다.

## 4. 정해야 하는 언어 설계 문제

아래는 정답이 하나가 아니라서 구현 전에 정해야 한다. 각 항목은 지금 동작, 후보, 영향을 적었다.

### 4.1 반복 제어 키워드 이름 — 결정: `중단` / `계속`

### 4.2 정수 오버플로 정책 — 결정: 실행 오류 + 감싸 도는 내장 함수

- **결정 전**: 감싸 돌기처럼 보이지만 실제로는 C++ 의 정의되지 않은 동작이었다.
- **고른 것**: 기본 산술은 넘치면 `시도` 로 잡을 수 있는 오류, 감싸 돌기가 의도인 계산은 `감싸더하기`·`감싸빼기`·`감싸곱하기`. 실수로 넘친 값을 조용히 넘기지 않으면서 해시도 비트 마스크 없이 쓸 수 있다.
- **고르지 않은 것**: 오류만 두는 안(해시마다 마스크가 필요), 감싸 돌기를 정의하는 안(실수로 넘친 값을 놓친다).

### 4.3 조건의 진리값 — 결정: 엄격

- **결정 전**: 의미 분석기가 타입을 아는 식은 논리 값만 받고(`만약 ("")` 은 오류), 변수는 실행 중에 진리값 규칙(`""`, `0` 은 거짓)을 썼다. 같은 값이라도 변수에 담느냐에 따라 결과가 달랐다.
- **고른 것**: 실행 중에도 `만약`·`반복` 조건과 `when` 가드가 논리 값이 아니면 오류. 결정 전 측정에서 저장소의 `.ksj` 73개와 kingsejong-examples 20개 중 논리 값이 아닌 조건을 쓴 곳은 없었다.
- **고르지 않은 것**: 의미 분석기 검사를 경고로 낮추는 안(기존 코드는 모두 돌지만 실수를 덜 잡고, 나중에 엄격하게 바꾸면 그때 호환이 깨진다).
- **범위 밖**: `!`, `그리고`, `또는` 는 진리값 규칙을 그대로 쓴다.

### 4.4 반복문 안 클로저가 잡는 변수 — 결정: 회차마다 새 환경

- **결정 전**: `i가 1부터 3까지 { f = 함수() { 반환 i } ... }` 로 모은 함수가 모두 `3` 을 돌려줬다. 반복 변수와 본문 변수를 모든 회차가 공유했다(평가기·VM 같음).
- **고른 것**: 회차마다 새 환경. 반복 변수와 본문에서 처음 만든 변수가 회차마다 따로 생기고 반복문 뒤에는 없다. 의미 분석기가 이미 본문 변수를 반복문 범위로 다루고 있어 실행 동작이 그 규칙과 맞게 됐다.
- **고르지 않은 것**: 반복 변수만 새로 만드는 안(Go 1.22, 규칙이 두 갈래), 지금처럼 공유하는 안(버그 원인이 남는다).
- **비용**: 30만 회 반복 두 개를 도는 측정에서 평가기 0.10초 → 0.14초, VM 0.10초 → 0.16초.

## 5. 진행 순서 제안

1. **기존 프로그램을 바꾸지 않는 추가** (결정 불필요): 3.2 글자 접근과 코드 값, 3.3 비트 연산과 리터럴, 3.5 `길이(딕셔너리)` 와 비교 함수 정렬, 3.6 명령줄 인자·표준 오류.
2. **새 키워드** (4.1 결정 후): 반복 제어, `각각`.

## 6. stdlib 일부를 KingSejong 코드로 다시 쓴 결과

### 6.1 문자 분류와 바이트 (2026-11-04)

5장 4단계로, C++ 내장 함수에 기대던 기능 중 libc 에 해당하는 것을 언어 자신으로 써 봤다(2026-11-04).

- **`stdlib/char`** (`ctype.h`): 글자 분류, 대소문자, 자릿값, 한글 음절 분해. `문자코드`·`코드문자`·비트 연산만으로 썼다.
- **`stdlib/bytes`**: UTF-8 인코딩·디코딩(과잉 길이·서로게이트 검사 포함), 16진수, Base64(RFC 4648 시험 벡터, 내장 `Base64_인코딩` 과 같은 결과), FNV-1a 64(공개 시험 값과 같음). 시험은 `tests/stdlib/char_bytes_test.ksj` 를 평가기와 VM 으로 돌린다.

쓰면서 부딪힌 것과 처리:

| 부딪힌 것 | 영향 | 처리 |
|---|---|---|
| 배열을 늘리는 방법이 `a = a + [x]` 뿐이라 매번 전체를 복사 | 3만 2천 개에 3.5초. 바이트 배열을 만드는 함수가 1MB 입력에서 쓸 수 없다 | 제자리에서 늘리는 `덧붙인다` 추가 (결정: 메서드 추가). 100만 개에 0.3초 |
| 평가기 평가 1000만 번·VM 명령 1억 개·5초에서 모든 프로그램을 멈추고 끌 수 없음 | 32만 바이트 UTF-8 디코딩, 1억 번 반복이 끝나지 않는다 | 파일 실행은 한도 없음, `--sandbox`·`--untrusted`·REPL·플레이그라운드는 기존 한도, `--max-time` 추가 (결정: 샌드박스에서만 한도) |
| 문자열 이어 붙이기가 O(n²) | 결과 문자열이 길면 느리다 | 언어는 그대로 두고 `조각_잇기`(둘씩 짝지어 합침, O(n log n)) 로 우회 |
| 이름이 숫자나 `_` 로 시작할 수 없음 (`16진수인가`, `_내부`) | 이름 규칙. 결함 아님 | `십육진수_…`, 접두어 없는 이름으로 씀. 모듈 안의 비공개 이름을 표시할 관례가 없다 |
| `문자열` 은 타입 키워드라 문장 맨 앞에 오면 변수 선언으로 읽힘 | `문자열 각각에 대해 …` 가 구문 오류 | 매개변수 이름을 `텍스트` 로 씀. 기존 `stdlib/string` 은 식 안에서만 써서 문제가 없다 |
| `stdlib/regex` 의 `숫자인가`·`한글인가` 와 이름이 겹침 | 두 모듈을 함께 가져오면 나중 것이 덮는다 | 글자 함수는 `_글자인가` 로 끝낸다 |

### 6.2 나머지 libc 영역 (2026-11-04)

- **`stdlib/convert`** (`strtol`, `strtod`, `printf`): 진법 정수 파싱·형식화(가장 작은 정수 포함), 실수 파싱·고정 소수점 형식화, `%[-+0][너비][.정밀도](d i x X o b f s c %)` 형식화.
- **`stdlib/text`** (`string.h`): KMP 검색, 마지막 위치, 개수, 접두·접미사, 다듬기, 토큰 나누기, 비교, 모두 바꾸기.
- **`stdlib/search`** (`bsearch`, `qsort`): 하한·상한·이진 탐색, 정렬 삽입, 제자리 힙 정렬, 제자리 뒤집기.
- 시험은 `tests/stdlib/libc_core_test.ksj` 를 평가기와 VM 으로 돌린다.

| 부딪힌 것 | 영향 | 처리 |
|---|---|---|
| `&&`·`\|\|` 가 오른쪽을 늘 평가 (평가기·VM) | `i < n && a[i]` 경계 검사가 인덱스 오류. 모든 문자열 훑기 루프가 깨진다 | 고침: 단축 평가 (결과 값은 그대로) |
| 실수 출력이 유효숫자 6자리, 보간만 소수 6자리 고정 | 값이 손실되고 정수와 구별되지 않아 언어로 짠 실수 파싱·형식화를 출력으로 검증할 수 없다 | Python 의 repr 로 통일 (결정: Python식) |
| `정수()`·`실수()` 가 앞부분만 읽음 (`"12abc"` → 12) | 잘못된 입력이 조용히 틀린 수가 된다 | 남는 글자는 오류, 실수 모양은 허용 (결정: 엄격·실수 모양 허용) |
| 실수 나눗셈이 나누는 수의 절댓값 < `1e-9` 이면 오류, VM 상수 접기만 계산 | `1.0 / 1e-10` 이 엔진마다 다르다 | 고침: 정확히 0 일 때만 오류 |
| 실수 `%` 가 없음 | `fmod` 를 쓸 수 없다 | 추가: `fmod` 규칙 (정수 `%` 와 같은 부호 규칙) |
| 비정규 실수 리터럴·`실수("5e-324")` 거부 | 표현할 수 있는 값을 읽지 못한다 | 고침: `strtod` 로 읽고 무한대가 되는 값만 거부 |
| 64비트 정수만 있음 | 정확히 반올림되는 `strtod` 를 언어로 쓸 수 없다. 무작위 3000개 중 251개가 마지막 자리에서 다르다(15자리 이하·작은 지수 2000개는 0개) | 문서에 적음. 큰 정수가 생기면 다시 본다 |
| 평가기 함수 호출 약 8.6µs (30만 번 2.6초, VM 0.21초) | 힙 정렬 10만 개가 평가기 41초, VM 5.9초 | 3.7 성능 단계로 미룸 |
| NaN 을 확인할 함수가 없음 | `값 != 값` 으로 확인하는데 린터 `no-self-comparison` 이 "항상 같은 결과" 라고 경고한다(실수에서는 틀린 경고) | 기록만. 린터는 `이름 = 함수(...)` 의 이름도 모르고 `<익명 함수>` 로 적는다 |

남은 것: 이 기능들을 쓰는 examples 레슨(다음 릴리스 태그 뒤), 그리고 남은 libc 영역(시간 형식화 `strftime`, 난수 생성기, 큰 정수).
